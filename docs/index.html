Llamatik API

Self-hosted inference server exposing the same surface as the Llamatik LlamaBridge, WhisperBridge, StableDiffusionBridge, and MultimodalBridge APIs.

  • JSON endpoints for embeddings and generation
  • SSE streaming endpoints for token/delta streaming
  • Text-to-image and text-to-video generation (stable-diffusion.cpp)
  • Speech-to-text transcription (whisper.cpp)
  • Multimodal / VLM image analysis (streaming SSE)
More information: https://helloreverb.com

Loads a Stable Diffusion model into memory. Must be called before any image or video generation endpoint. Use /stablediffusion/release to free resources when done.

Requires a video-capable model loaded via /stablediffusion/init with companion files. The response contains the full packed frame buffer Base64-encoded.

[frame_1_rgba: width * height * 4 bytes]

get /models
List currently loaded models (modelsGet)

Returns the loaded state of every inference bridge. Only model filenames are returned — full server paths are never exposed.

Each bridge reports loaded: true/false and, when loaded, the filename of the active model. The Stable Diffusion bridge also reports companion files (VAE, T5-XXL, CLIP vision). The multimodal bridge reports the projector filename alongside the model.

This endpoint follows the same REQUIRE_INFERENCE_AUTH setting as all other inference endpoints.

Return type

ModelsStatusResponse

Example data

Content-Type: application/json
{
  "generation" : {
    "loaded" : "",
    "capabilities" : "",
    "model" : ""
  },
  "multimodal" : {
    "loaded" : "",
    "mmproj" : "",
    "model" : ""
  },
  "embedding" : {
    "loaded" : "",
    "model" : ""
  },
  "stableDiffusion" : {
    "loaded" : "",
    "clipVision" : "",
    "t5xxl" : "",
    "model" : "",
    "vae" : "",
    "supportsVideo" : ""
  }
}

Produces

This API call consumes the following media types via the Content-Type request header:
  • application/json

Request body

body TranscribeSegmentsRequest (required)
Body Parameter —

Return type

TranscribeSegmentsResponse

Example data

Content-Type: application/json
{
  "json" : ""
}

Produces

This API call produces the following media types according to the Accept request header; the media type will be conveyed by the Content-Type response header.
  • application/json

Responses

200

JSON document with segments, timestamps, and speaker turns TranscribeSegmentsResponse

400

Transcription failed
